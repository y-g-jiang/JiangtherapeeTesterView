# JPTC Collect — 贡献者采集与分析工具

设计文档 · 2026-08-11 · 阶段 0–2

## 1. 这是什么

一个发到别人手上的桌面应用。对方按流程拍完，把 RAW 拖进来，工具解码、统计、产出**可回收的数据文件**寄回。分析和结论仍然在 [ptc-compare](../../../../ptc-compare/) 那边做。

对方是摄影师，不是工程师。所以工具的第一职责不是算得快，是**让不合格的数据在对方那里就被拦下**，而不是在我这里被发现。

### 非目标

- 不做任何结论展示（那是 ptc-compare 的事）
- 不修图、不渲染、不导出可视图像
- 不联网、不上传（产出文件由对方自行寄回）

## 2. 三个入口与它们的依赖

```
入口 3  黑场对（每 ISO 两张，全 ISO 段）
          ├─ BL(ISO)        每个 ISO 的黑电平
          ├─ RN_DN(ISO)     每个 ISO 的时域读噪
          └─ 噪声谱          差分后逐通道 FFT
                │
入口 2  ISO gain 阶梯（固定场景，扫 ISO）
          └─ 需要 BL(ISO) ──┘
          └─ 相对 gain 曲线 g(ISO)/g(ref)
                │
入口 1  PTC 平场对（单 ISO，多快门）
          └─ 需要 BL ───────┘
          └─ 绝对 g(ref)、PRNU、FWC
                │
          三者合成：全 ISO 段绝对 gain、以电子计的读噪、动态范围
```

**拍摄顺序与构建顺序都是 3 → 2 → 1。**黑电平是另外两个入口的输入，先有它，后面两步才有意义。

## 3. 运行形态

Electron + React + TypeScript。

**RAW 解码走 WASM，不用原生插件。**理由不是省事：采集端和分析端必须用**同一个解码器**，否则两边对同一个文件的黑电平、位深、CFA 相位的理解可能不一致，而这种不一致会静默地污染所有下游数字。主项目已有 `joraw.wasm` 与 `LibRaw-Wasm`，直接复用。

只需要 **raw mosaic + EXIF**，不需要去马赛克、不需要色彩。LibRaw 的 `unpack()` 就够，跳过 `dcraw_process()`——这是性能的主要来源，25 MP 一张约几百毫秒，四十张十几秒，可以接受。

## 4. 阶段 0：共享地基

三个入口全部压在这上面，先定死。

### 4.1 拍摄模式录入

**点击任何输入之前必须填完。**未填完的按钮禁用，不是提交后报错。

| 字段 | 取值 | 为什么必须 |
|---|---|---|
| 机身 | 自由文本 + 从 EXIF 预填 | |
| 固件版本 | 自由文本 + 从 EXIF 预填 | 同机身不同固件的读出可以完全不同 |
| 快门类型 | `mech` / `efcs` / `elec` | 入口 2 的快门标称值准不准全靠它 |
| 压缩 | `lossless` / `uncompressed` / `lossy` | 有损压缩会改噪声统计，必须能筛掉 |
| 位深 | 12 / 14 / 16 | |
| **量化步长** | 由位深与容器推出，可手动覆盖 | 见 §4.3，全表最关键的一个数 |
| 镜头 | `none-bodycap` / 型号 | 黑场必须机身盖；有镜头的黑场不可信 |
| 长曝光降噪 | 必须勾「已关闭」 | 勾不上就不让继续 |
| 高感降噪 | 记录设置值 | 部分机器会动 RAW |
| 环境温度 | 可选，摄氏 | 暗电流与温度强相关 |

### 4.2 文件命名

产出文件名编码模式，人眼可读、机器可解析：

```
<brand>-<model>_<fw>_iso<n|range>_<shutter>_<compression>_<bitdepth>bit_<entry>_<date>.<ext>

panasonic-s1m2_v1.2_iso100_mech_lossless_14bit_ptc_20260811.csv
panasonic-s1m2_v1.2_iso50-25600_elec_lossless_14bit_dark_20260811.csv
panasonic-s1m2_v1.2_iso50-25600_elec_lossless_14bit_isogain_20260811.csv
```

同样的字段也写进文件头，**文件名与文件头不一致时以文件头为准**，并在导入侧报警——文件名会被人改，文件头不会。

### 4.3 量化步长的判定

分析端做 Sheppard 修正（`sigma^2_true = sigma^2_measured - q^2/12`）必须知道 `q`，而 `q` **从统计量里反推不出来**。工具在这里有优势：它能看到原始码值。

判定方法：取一张暗场的原始 mosaic，求相邻码值之差的非零最小公约数。12 bit 装进 16 bit 容器的文件，所有码值都是 16 的倍数，`q = 16`；14 bit 原生则 `q = 1`。

结果写进文件头 `#AdcStep:`。允许手动覆盖，但默认由实测决定，不由位深猜测。

### 4.4 合格性检查

在对方那里就拦住，每条都要给出人话理由与补拍建议：

| 检查 | 判据 |
|---|---|
| 帧数成对 | 每个设置恰好两张 |
| 设置一致 | 一对之内 ISO、快门、光圈、压缩必须相同 |
| 时间接近 | 一对之内拍摄时间差超过阈值就警告（温漂） |
| 无长曝光降噪 | EXIF 能读则读，读不到则依赖勾选 |
| 黑场确实是黑的 | 均值减黑电平后接近零，且无亮区（漏光） |
| 平场确实是平的 | 中心区域梯度小于阈值 |
| 未钳位 | 逐通道统计顶到上限的像素比例 |
| 位深与压缩符合声明 | 与 EXIF/解码结果对账 |

## 5. 阶段 1：入口 3 —— 黑场对

### 5.1 拍摄流程（呈现给对方）

机身盖，无镜头。最低 ISO 到最高 ISO，每档两张。快门任意但一对之内相同，建议用能达到的最短快门以压低暗电流。长曝光降噪关闭。

### 5.2 计算

对每个 ISO：

1. 解码两张的 mosaic，拆成 R / G1 / G2 / B 四个平面
2. `BL_ch = mean(A_ch)` 与 `mean(B_ch)`，两者都记
3. `D = A − B`，逐通道
4. 坏点剔除：对 `D` 做迭代 sigma clip，**k = 3.5**，收敛后把 std 除以 `sqrt(0.9969)` 补回被剪掉的真噪声

   固定偏移的热点在差分里精确抵消，所以 `D` 上剩下的大偏离只可能是时域异常像素或宇宙线；这使差分帧成为找它们的正确地方。剪切会连带削掉要测的噪声，截断高斯的方差有闭式解，`k=3.5` 处修正后偏差 ≤ 0.1%，且剔掉 96% 的宇宙线。`k < 3` 时迭代剪切会过收敛，闭式修正不再成立——**不要放宽到 3 以下**。
5. `RN_DN(ISO, ch) = std_clipped(D_ch) / sqrt(2) / sqrt(0.9969)`
6. 谱：对每个通道平面的 `D` 做二维 Welch FFT

   **必须逐通道做，不能对 mosaic 整幅做。**CFA 的两像素周期会在谱上产生巨大假峰，把真实结构淹没。数学从主项目 [`calculate2DWelchSpectrumFromPlane`](../../../../Jiangtherapeemaster/services/rawProcessor.ts) 搬，分段尺寸取 2 的幂，Hanning 窗。
   
   差分使功率翻倍，**谱值除以 2** 才是单帧的。

### 5.3 产出

两个文件。标量表：

```
#Format: JPTC-DARK/1
#AdcStep: 1
#ClipSigma: 3.5
#ClipCorrection: 0.9969
… 模式字段 …
ISO,ShutterSec,N,FileA,FileB,
R_BLa,G1_BLa,G2_BLa,B_BLa,
R_BLb,G1_BLb,G2_BLb,B_BLb,
R_StdA,G1_StdA,G2_StdA,B_StdA,
R_StdB,G1_StdB,G2_StdB,B_StdB,
R_StdDiff,G1_StdDiff,G2_StdDiff,B_StdDiff,
R_Clipped,G1_Clipped,G2_Clipped,B_Clipped
```

`StdDiff` 是 `A−B` 的标准差**原值，不除 √2，不做 Sheppard 修正**。剪切已经做了（因为它需要原始像素，分析端做不到），剪切参数写在头里，修正是可复算的。

谱另存二进制，每 (ISO, 通道) 一张二维功率图，附维度与频率标度。

## 6. 阶段 2：入口 2 —— ISO gain 阶梯

### 6.1 测量原理

固定场景、固定光圈，则每通道

    DN − BL = Φ · t / g

于是任意两档

    g₁ / g₂ = (t₁ / t₂) · (DN₂ − BL₂) / (DN₁ − BL₁)

**不要求「曝光正确」。**只要电平落在不钳位、不埋进底噪的区间即可。工具实测每张的电平，测光误差因此完全不进入结果——若依赖「曝光正确」，测光差 1/3 档就是 26% 的 gain 比误差。

暗电流在这里自动抵消：它也正比于 `t`，等效于 `Φ → Φ + D`，比值不变。这正是长曝光降噪必须关闭的原因——它只在部分帧上减暗电流，那才会破坏比例。

### 6.2 两种阶梯，都支持

**同快门配对（推荐）。**每个快门时间下拍相邻两档 ISO：

    快门 t_a:  ISO₁ → L₁,  ISO₂ → L₂   ⟹  g₁/g₂ = L₂/L₁
    快门 t_b:  ISO₂ → L₃,  ISO₃ → L₄   ⟹  g₂/g₃ = L₄/L₃
    链式相乘

`t` 从头到尾不出现。只要求快门在**同一对之内可重复**，不要求它准。这消掉了本方法最大的系统误差:从 RAW 读到的是**标称**快门时间，机械快门的实际值系统性偏离标称，而这个偏离读不出来。

**自动快门扫 ISO（快速）。**你原来的流程，一档 ISO 一张。快，但吃快门标称值的准确度。

两条路径都跑，把两条曲线画在一起。**它们分歧的地方就是快门标称值不准的地方**——这本身是有用的产出，不是缺陷。

### 6.3 拍摄流程（呈现给对方）

三脚架或把机器压在稳固处，对准均匀墙面。固定光圈——**优先手动光圈镜头**，电子光圈每次曝光重新收缩会带来重复性误差。光源须为直流或日光：市电 LED / 荧光灯在 1/500 s 下会造成大幅电平波动。

### 6.4 产出

```
#Format: JPTC-ISOGAIN/1
#Ladder: paired-shutter | auto-shutter
… 模式字段 …
ISO,ShutterSecNominal,Aperture,File,PairGroup,N,
R_Mean,G1_Mean,G2_Mean,B_Mean,
R_Std,G1_Std,G2_Std,B_Std,
R_ClipFrac,G1_ClipFrac,G2_ClipFrac,B_ClipFrac
```

**只记电平，不算 gain 比。**比值的算法（用哪条链、怎么加权）会演进，而电平不会。原始记录留在原始层。

## 7. 阶段 3：入口 1 —— PTC 平场对（本文档只作占位）

单 ISO，多快门，两两配对的平场。取中心 512×512 mosaic（= 每通道 256×256，65536 个样本），差分，k=3.5 剪切与修正，逐通道记 `StdA` / `StdB` / `StdDiff`。

产出即已定稿的 **JPTC/2** schema，直接进 ptc-compare。

## 8. 与 ptc-compare 共享什么

只有两样：**CSV schema** 与**拟合数学**。两边各存一份拷贝，用同一组黄金测试钉住数值一致——把它们做成 npm 包会让两个仓库的发布节奏绑死，收益不抵成本。

不共享 UI、不共享构建、不共享依赖。ptc-compare 是你自己的分析页，ptc-collect 是发出去的采集端，混在一起会把你的机型库随应用一起发出去。
